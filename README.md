## 3. Выбор окружения

Выбран **venv**, а не conda, по следующим причинам:

- входит в стандартную библиотеку Python, ничего дополнительно устанавливать не нужно;
- для курса достаточно пакетов из PyPI (pandas, numpy, matplotlib, seaborn, jupyter), тяжёлые бинарные зависимости, ради которых нужен conda, не требуются;
- список зависимостей фиксируется в `requirements.txt`, и любой может воспроизвести окружение одной командой;
- окружение лёгкое и находится внутри папки проекта (`.venv/`), поэтому не мешает другим проектам.

Минус venv: он не управляет версией самого Python. Нужный Python (3.9 или новее) должен быть установлен заранее.

Библиотеки:

| Библиотека | Зачем нужна |
|---|---|
| pandas | загрузка и анализ табличных данных |
| numpy | числовые операции (устанавливается вместе с pandas) |
| matplotlib | построение графиков |
| seaborn | статистические графики и загрузка датасета |
| jupyter | запуск notebook |

## 5. Установка и запуск

Все команды выполняются в папке проекта (PowerShell на Windows).

1. Создать виртуальное окружение:
   ```
   python -m venv .venv
   ```
2. Активировать его:
   - Windows (PowerShell): `.venv\Scripts\Activate.ps1`
   - Windows (cmd): `.venv\Scripts\activate.bat`
   - macOS / Linux: `source .venv/bin/activate`

   Если в начале строки появилось `(.venv)`, окружение активно.
3. Установить зависимости:
   ```
   pip install -r requirements.txt
   ```
4. Запустить Jupyter:
   ```
   jupyter notebook
   ```
5. В открывшемся окне браузера перейти в папку `notebooks/` и открыть `01_tips_eda.ipynb`.
6. Выполнить **Kernel → Restart & Run All** (в JupyterLab: Kernel → Restart Kernel and Run All Cells). После этого сохранить файл (Ctrl+S), чтобы вывод ячеек остался в файле.

### Возможные проблемы

- **`No matching distribution found for jupiter`.** В имени пакета опечатка: правильно `jupyter` (через «y»).
- **PowerShell не разрешает активировать окружение.** Выполнить `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`, затем повторить активацию.
- **`ModuleNotFoundError` в notebook.** Jupyter запущен вне окружения. Закрыть его, активировать `.venv` и запустить `jupyter notebook` заново.
- **Датасет не скачивается.** Нет интернета. Положить файл `tips.csv` в папку `data/` вручную.

## 6. Ход работы

Notebook построен по общепринятой логике первичного анализа данных (EDA): от общего к частному.

**Шаг 1. Загрузка.** Данные читаются из `data/tips.csv` в таблицу pandas `df`. Первые строки выводятся через `df.head()`, чтобы убедиться, что файл прочитан правильно.

**Шаг 2. Структура таблицы.** Выводятся:
- размер таблицы (`df.shape`): число строк и столбцов;
- типы столбцов (`df.dtypes`): какие признаки числовые, какие текстовые;
- число пропусков по столбцам (`df.isna().sum()`);
- базовые статистики числовых признаков (`df.describe()`): среднее, стандартное отклонение, минимум, квартили, максимум;
- сводка по категориальным признакам (`df.describe(exclude="number")`): число уникальных значений и самое частое из них.

**Шаг 3. Визуализация.** Построены три графика:

| № | График | Что показывает |
|---|---|---|
| 1 | Гистограмма `total_bill` с кривой плотности | форму распределения числового признака: где основная масса счетов и есть ли длинный хвост |
| 2 | Столбчатая диаграмма числа счетов по дням недели | соотношение категорий: в какие дни данных больше, а в какие меньше |
| 3 | Диаграмма рассеяния `total_bill` – `tip` с разбивкой по `time` | связь между счётом и чаевыми |

Требовалось не менее двух графиков (распределение числового признака и соотношение категорий), поэтому графики 1 и 2 закрывают требование полностью, а график 3 добавлен как дополнительный.

**Шаг 4. Наблюдения.** Для наблюдений введён производный признак `tip_pct`, то есть доля чаевых от счёта в процентах (`tip / total_bill * 100`). Он нужен, потому что абсолютная сумма чаевых зависит от размера счёта, а доля позволяет сравнивать счета разного размера. Дополнительно считаются корреляции, доли по размеру компании и по дням недели, а также средняя доля чаевых по дням.

## 7. Наблюдения о данных

В последней Markdown-ячейке notebook сформулированы три содержательных наблюдения. Ни одно из них не повторяет вывод `describe()`.

1. **Чаевые пропорциональны счёту.** Сумма чаевых растёт вместе со счётом, а доля чаевых от счёта держится примерно на одном уровне. Корреляция суммы счёта с долей чаевых близка к нулю. Практический вывод: для прогноза чаевых полезнее предсказывать долю, а не абсолютную сумму.
2. **Данные несбалансированы по дням недели.** Основная масса счетов приходится на выходные, а в пятницу наблюдений меньше всего. Любые выводы по пятнице опираются на малую выборку и менее надёжны.
3. **Типичный посетитель — компания из двух человек, а распределение счёта скошено вправо.** Большинство счетов относится к компаниям из двух человек. У суммы счёта длинный правый хвост из редких крупных счетов, поэтому среднее значение выше типичного.
